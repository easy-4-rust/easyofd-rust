# easyofd-rust v1.0.0 版本规划

> **日期**: 2026-08-12
> **状态**: 已批准
> **基线**: workspace version 1.0.0, edition 2024, rust-version 1.88

## 1. 背景

easyofd-rust 经过 6 个主要阶段的迭代开发，已从 v0.1.0 基础读写库成长为功能完整的 OFD 文档操作库。当前状态：

- 18 个 crate 的 Rust workspace
- 2696 个测试全部通过
- roundtrip_diff 60 样本零偏离
- 类型覆盖 99.4%（484/487）
- 行覆盖率 ~93%
- CI 矩阵全绿（ci / coverage / security / fuzz / release）
- cargo-fuzz 4 个 target

本文档定义 v1.0.0 的发布范围、质量门禁，以及后续版本的候选方向。

### 2.3 发布条件

v1.0.0 发布需满足以下全部条件：

1. 上述质量门禁全部通过
2. `cargo doc --workspace` 无警告
3. crates.io 元数据完整（description / license / repository / keywords）
4. CHANGELOG.md 完整记录
5. 用户指南文档（docs/usage-guide.md）更新

## 3. 后续版本候选方向

### 3.1 v1.1.0: 易用性增强

| 方向 | 内容 | 优先级 |
|---|---|---|
| **EasyOfd 门面完善** | 暴露全部 P0-P6 新增功能到 facade API | 高 |
| **Examples 扩展** | 新增 10+ 顶层 examples（签名、加密、版面、批注） | 高 |
| **文档覆盖率** | `cargo doc --workspace` 无警告，所有 public API 有 doc comment | 高 |
| **用户指南更新** | 更新 docs/usage-guide.md 覆盖全部功能 | 中 |

### 3.2 v1.2.0: PDF 转换增强

| 方向 | 内容 | 优先级 |
|---|---|---|
| **OFD → PDF 保真度** | 提升 printpdf 输出质量（字体嵌入、坐标精度） | 高 |
| **PDF → OFD 解析** | 增强 lopdf 解析能力（复杂 PDF 结构） | 高 |
| **PDF L3 验证** | 建立 PDF 输出的比对验证体系 | 中 |

### 3.3 v2.0.0: 高级特性

| 方向 | 内容 | 优先级 |
|---|---|---|
| **流式大文件** | 100MB+ OFD 文件的常数内存处理 | 高 |
| **异步 I/O** | 可选 async 运行时支持（tokio） | 中 |
| **WASM 支持** | 编译到 wasm32-unknown-unknown | 中 |
| **C FFI** | 提供 C 绑定供其他语言调用 | 低 |

### 3.4 长期方向

| 方向 | 内容 | 说明 |
|---|---|---|
| **OCR 集成** | 可选 OCR 引擎集成 | 超出库职责，建议作为独立 crate |
| **自定义字体生成** | CJK 字体子集化 | 独立工程，建议使用现有字体资源 |
| **分布式签名** | 多方协同签名 | 需求不明确，暂不规划 |

## 4. 技术债清单

| 项目 | 说明 | 建议版本 |
|---|---|---|
| PDF 字节级比对 | L3 验证排除为独立里程碑 | v1.2.0 |
| iText 类型排除 | 3 个 iText 7 依赖类型 | 维持现状（纯 Rust 约束） |
| 部分文件 >800 行 | 少数文件可能超过 800 行限制 | v1.1.0 审计 |
| doc comment 覆盖 | 部分 public API 缺少文档 | v1.1.0 |

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| OFD 规范复杂度 | 部分边缘场景未覆盖 | 逐版本扩展，损失报告透明 |
| PDF 转换精度 | 布局丢失 | 明确限制，提供损失报告 |
| 签章密码学依赖 | 引入 C/C++ 依赖 | 优先纯 Rust SM2 实现 |
| 大文件性能 | 超时 | 流式处理 + 进度回调 |
